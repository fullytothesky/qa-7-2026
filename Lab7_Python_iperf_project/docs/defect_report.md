# Навчальний defect report DR-01

## Назва

Клієнт не може підключитися до iperf3-сервера через невідповідність портів.

## Контекст і тип проблеми

Навмисно створена помилка конфігурації для перевірки обробки відмови підключення. Звіт описує стан тестового середовища, за якого вимірювання неможливе.

## Середовище

ПК1 10.0.0.1, ПК2 10.0.0.100; Ubuntu Server 24.04.3 LTS ARM64; iperf3 3.16, Python 3.12.3, pytest 9.2.0, Paramiko 5.1.0.

## Передумови

Сервер слухає TCP-порт 5201. Для клієнта вибрано порт 5202. SSH-з'єднання з ПК1 працює.

## Кроки відтворення

1. У папці проєкту активувати .venv та встановити LAB_SSH_PASSWORD у поточному сеансі.
2. Виконати `python -m pytest -v -s --tb=short test_iperf.py --client-port 5202 --result-name pytest_connection_error`.
3. Переглянути stderr, результат assert та підсумок pytest.

## Очікуваний стан справного налаштування

Клієнт звертається до того самого порту, який слухає сервер; з'єднання встановлюється та отримуються інтервали вимірювання.

## Фактичний результат

`Connection refused`. Тест завершується на `assert not error`; підсумок `1 failed in 0.44s`, код завершення 1. Вихідний файл results/pytest_connection_error.txt порожній; stderr містить повідомлення про відмову підключення. Фікстура виконує teardown.

## Причина та рекомендоване виправлення

Порт клієнта 5202 не збігається з портом сервера 5201. Використовувати `--client-port 5201` або типовий запуск без перевизначення порту. Позитивний запуск із 5201 окремо зафіксований у TC-05.

## Вплив і статус

Вплив: блокує вимірювання пропускної здатності у цьому сценарії. Статус: умови відтворення підтверджено; описане рекомендоване виправлення. Докази: evidence/pytest_connection_error.png та results/pytest_connection_error.stderr.
